  - **What was varied, and what was held**: both completed runs use the same
    freshly-assembled DUT, the same generated deck, the same `.options`, the
    same corner, the same `vctrl_ic` = 2.7 V released-clamp seed and the same

    (2 us vs. 250 ns), via the `SIM_WINCAP` override this record's PR added to
    `sim/lock-time/testbench/run.sh` for exactly this purpose. The override
    appears in the work-directory tag, so a short-window log cannot be
    silently reused for a full-window record.
  - **Why a 250 ns window is a legitimate measurement here and not a
    shortcut**: the mechanism in question is per-feedback-edge, not
    cumulative -- #52's artefact is "the integrator steps clean over the set
    pulse, so the PFD never sees that edge", which either happens on a given
    edge or does not. At N=4 the reference period is 50 ns, so 250 ns is
    5 reference cycles: enough to observe the per-edge PFD response and the
    direction and rate of Vctrl travel, and **not** enough to claim a settled
    Vctrl or a lock verdict. The short window is reported as evidence for the
    former only. Its cost ratio to the 2 us window (below) is what made the
    compliant arms attemptable at all on this host.
  - **Measurement method**: internal-step and duty statistics are measured
    from each run's committed `waveform.csv` by `sim/lib/waveform_stats.awk`,
    added by this record's PR. `wrdata` dumps the vectors ngspice holds after
    `run`, which for a transient are the **accepted internal timepoints**, not
    the print grid -- so the committed CSV is a direct, auditable record of
    the integrator's own step sequence. **Validated before use**: the script
    reproduces every published figure of `20260801-101734-5eb00db.md` from
    that record's own three artifacts exactly (mean internal step 0.230 ns /
    0.232 ns / 1.756 ns; 1037 of 1139 steps over the set pulse; `up` duty
    86.7%; `vctrl_final` 3.13821 V). It is the same measurement, now
    re-derivable rather than recomputed per session.

      convention accounts for a ~0.2 pt difference against
      `20260801-073931-eec269e.md`'s own reported duty.

  ### 2. #52's documented artefact mechanism is geometrically excluded at 250 ps

  | Artifact | Ceiling | Mean step | **Max step** | Steps longer than the 0.33 ns set pulse | Steps per set pulse |
  |---|---|---|---|---|---|
  | This record, 2 us arm | 250 ps | 0.2298 ns | **0.250 ns** | **0 of 8705 (0.0%)** | 1.44 |
  | This record, 250 ns arm | 250 ps | 0.2248 ns | **0.250 ns** | **0 of 1112 (0.0%)** | 1.47 |
  | `output-range` `lo` (committed, for contrast) | 2 ns | 1.756 ns | 2.0 ns | 1037 of 1139 (91.0%) | 0.19 |
  | #52's demonstrated-fatal case | 500 ps | 0.38 ns | -- | -- | ~0.87 |

  The mechanism #52 documents is a *skip*: the integrator's step is long
  enough to jump clean over the set pulse, so the PFD never sees that feedback
  edge (9 of 16 missed at a 500 ps ceiling). That requires an interval between
  consecutive accepted timepoints **longer than the set pulse**.

  At a 250 ps ceiling **no such interval exists**: the largest accepted step
  in either arm is 0.250 ns, and the shortest set pulse #52 measured is
  0.33 ns. An interval of at most 0.250 ns cannot contain a 0.33 ns window,
  so **at least one accepted timepoint falls inside every set pulse, on every
  edge, necessarily** -- not on average, and not with high probability. This
  is a geometric consequence of `max step < min set pulse`, and both arms
  measure it directly (0 of 8705 and 0 of 1112 steps over 0.33 ns).

  **Consequence for `20260801-101734-5eb00db.md`'s qualification.** That
  record's central worry was a *coincidence of signature*: the `relock`
  records' empirical description matches #52's artefact description phrase
  for phrase. Section 2 breaks the coincidence in one direction -- the
  artefact as #52 documented it is not available at the ceiling those records
  ran at, so the matching phrasing cannot be attributed to that mechanism.
  The qualification does **not** disappear: 1.4 steps per set pulse is still
  well under the 3-4 the bound targets, so the latch response is
  under-resolved and a residual accuracy question remains. But it narrows from
  "this may be the documented artefact" to "this is not the documented
  artefact; it may still be under-resolved."

  **The contrast row matters as much as the two new ones.** `output-range`'s
  `lo` edge, at 91% of steps longer than the entire set pulse, sits squarely
  inside the mechanism this section excludes for `lock-time`. The two
  campaigns were qualified together by `20260801-101734-5eb00db.md`; on this
  evidence they are in materially different positions, and `output-range`'s
  `lo` remains the one that should be re-run first.
