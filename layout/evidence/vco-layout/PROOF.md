# VCO ring block — real transistor-level layout DRC run (issue #293)

Generated by `python3 -c "from vco import ring; ring.build(...)"` (see
`layout/pll_top/vco/ring.py`) followed by `python3 layout/run_pv.py drc
vco_ring.gds --top vco_ring --offgrid`. See `layout/pll_top/vco/ring.py`'s
module docstring for the full scope of what this pass draws and what it
defers, and `layout/floorplan/PLL-FLOORPLAN.md` §1/§5 for the isolation and
area-budget plan this layout implements.

## What this is, and is not

This **is** a real, DRC-clean transistor-level layout — not a boundary-layer
placeholder like `layout/evidence/floorplan-skeleton/`. Every shape is drawn
on the PDK's real device/interconnect layers (`comp` 22/0, `poly2` 30/0,
`contact` 33/0, `nplus` 32/0, `pplus` 31/0, `nwell` 21/0, `metal1` 34/0) —
confirmed against `nfet_03v3`/`pfet_03v3`'s own layer recipe in
`$PDK_ROOT/libs.tech/klayout/lvs/rule_decks/mos_extraction.lvs`
(`extract_devices(mos4('nfet_03v3'), ...)` / `pfet_03v3`) — and the DRC run
below exercises the PDK's full ~50-table `main` rule deck against that real
geometry (`comp.drc`, `poly2.drc`, `contact.drc`, `nplus.drc`, `pplus.drc`,
`nwell.drc`, `metal1.drc`, and everything else the deck runs), not the
layer-(0,0) `DIEAREA` marker `layout/floorplan/skeleton.py` uses (which
carries no rule at all).

**Scope, disclosed explicitly (issue #293 was scoped down, not completed
whole):**

| Drawn for real, this pass | Deferred to follow-up issue(s) |
|---|---|
| 5-stage current-starved ring (`vco_stage.sch` x5) | Bias generator (`vco_bias.sch`) |
| Dedicated VCO guard ring (outer `p`/`GND_VCO`, inner `n`/`VDD_VCO` tap band) | 3-cascade band-select mirror (common-centroid) |
| Carried-forward 22 pF decap footprint (unchanged from `vco.sch`/skeleton.py) | 3-stage output buffer |

`ring.py`'s module docstring states the rationale: the ring is the
layout-critical path PLL-FLOORPLAN.md §1 names explicitly ("an under-tapped
ring that trips DRC or adds asymmetric parasitic loading to one stage eats
directly into [DR-003's] margin"), and its own guard ring + decap are two of
issue #293's other acceptance-criteria bullets — this is the largest
coherent, independently-DRC-provable slice of the full issue scope, not a
placeholder standing in for the rest. `VBP`/`VBN` (bias inputs) and `Y5`
(pre-buffer ring output) are left as named Metal1 pins at the block boundary
for the follow-up issue(s) to land against.

Full-custom construction note (see `primitives.py`'s module docstring for
detail): every transistor is its own self-contained comp/poly/implant
island, wired to its neighbours only through Metal1 + contacts — even where
`vco_stage.sch` stacks two devices in series (e.g. `MPH`→`NH`→`MP`). This
costs area against a maximally dense shared-diffusion stack, but keeps every
DRC-relevant interaction local to one device's own geometry.

## Tap pitch (test plan edge case)

`layout/tests/test_vco_layout.py`'s `TapPitchTests` checks this
independently in pure Python (`ring.max_pmos_tap_distance_um()` /
`max_nmos_tap_distance_um()`), not just "the DRC run happened to pass":

| | Worst-case distance to nearest tap | Bound (PLL-FLOORPLAN.md §1) |
|---|---|---|
| PMOS (n-well tap band) | 2.29 µm | ≤ 15 µm |
| NMOS (outer p-ring) | 5.88 µm | ≤ 15 µm |

Both are well inside the 15 µm bound with real margin (not a rounding-error
pass), because every device sits inside a compact, fully-packed 5-stage row
with a tap band running the full row length on both the substrate and
n-well sides — not because the block happens to be small enough that a
single perimeter tap would have sufficed.

## Footprint vs. the ROM estimate (issue #293 AC — deviation disclosed)

Real footprint (outer p-guard-ring extent, `ring.footprint_um()`):
**177.4 × 18.66 µm ≈ 3,310 µm²** (this pass's drawn sub-portion only — ring +
guard ring + decap, not the full block; the bias generator, band-select
mirror, and output buffer this pass defers will add more).

This deviates from `layout/floorplan/PLL-FLOORPLAN.md` §5's 140×100 µm ROM
estimate in **both directions**, disclosed rather than silently absorbed:

* **Wider** (177 vs. 140 µm): the 5 stages are placed in a single row,
  full-custom, each transistor its own diffusion island wired by Metal1
  (see `primitives.py`'s docstring) — a denser layout (e.g. folding the row
  into two) is a real future optimization, out of this pass's scope.
* **Shorter** (18.7 vs. 100 µm): the ROM box's height assumed room for
  *every* VCO sub-block (ring + bias + mirror + buffer) stacked together;
  the ring alone is a thin horizontal band.

`layout/floorplan/skeleton.py`'s `VCO_CORE` placeholder is **augmented**
(not replaced) per issue #293's own acceptance criterion: a new `VCO_RING`
block carries this real footprint, and `VCO_CORE.w` is widened from 140 to
185.5 µm so it stays a real (not stale) bound on the ring's own width, while
`VCO_CORE.h` is left at the ROM value — reserved for the sub-blocks this
pass does not yet draw.

## Friction protocol (CLAUDE.md)

No new `klayout-tools` gap was hit drawing this real (not placeholder)
transistor-level geometry — this pass builds geometry directly against
`klayout.db` (the same approach `layout/harness/cell.py` and
`layout/floorplan/skeleton.py` already use) and runs the PDK's own official
DRC deck through the standalone KLayout binary, exactly as
`layout/README.md`'s "Why this isn't `klt drc`" section already documents
and justifies for this whole flow. The existing friction log entries there
(no `klt lvs`, `klt drc`'s curated rule subset) remain the complete list;
nothing new to add.
