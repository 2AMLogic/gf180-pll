# VCO supply decap drawn as real `cap_nmos_03v3` devices (issue #759)

`design/netlist/vco.spice` puts a 22 pF decap on the VCO supply:

```
XCDEC1 VDD_VCO GND_VCO cap_nmos_03v3 c_width=50u c_length=50u m=1
XCDEC2 VDD_VCO GND_VCO cap_nmos_03v3 c_width=50u c_length=50u m=1
```

Until this record, `vco_block` carried that pair as two layer-(0, 0) 50 x 50 um
rectangles (`block.decap_boxes_um()`), no foundry rule or LVS rule saw them,
and the block's LVS reference left `XCDEC1`/`XCDEC2` out
(`PROOF-block.md`, `PROOF-lvs.md`: "deliberately **not** emitted"). The
assembled `pll_top` inherited the markers, so the assembled chip had no
physical VCO decap. They are now two real devices of the device class the
schematic names, in the LVS reference, and in the assembled chip exactly once.

**Verdict in one line:** on `gf180mcuD` (KLayout 0.28.16) the regenerated
`vco_block` is **DRC-clean with the off-grid class enabled (0 violations)** and
**LVS-matches a reference that includes both capacitors**, the extracted
netlist holds the capacitors as `cap_nmos_03v3` (never `_b`), 2 x 2,500 um^2 =
22 pF at the deck's nominal, gate on `VDD_VCO` and n+ on `GND_VCO`; the block
grew from 172.52 x 184.48 um to 226.69 x 184.48 um (+9,993 um^2) to make room;
the assembled `pll_top` bounding box and its area are unchanged
(407,776.2 um^2) and its single DRC violation is still the loop filter's
inherited `MIMTM.3`. Nothing here is a simulation or a performance claim.

## What is drawn

`primitives.mos_cap_nmos()` follows the PDK's own `draw_cap_mos.py`
(`type="cap_nmos"`), not the loop filter's `cap_nmos_03v3_b` generator:

| Layer | Shape | Why |
|---|---|---|
| `comp` (22/0) | 51.2 x 50 um slab | 50 um of gate length between two 0.6 um diffusion strips |
| `poly2` (30/0) | 50 x 51.24 um, one gate bar | gate = `poly2 AND comp` = 50 x 50 um = the device's W x L |
| `mos_cap_mk` (166/5) | = comp | makes the gate region a capacitor, not a transistor |
| `lvpwell` (204/0) | = comp | the deck's `P2` plate is `lvpwell_con` (`moscap_extraction.lvs`); the pcell draws it |
| `nplus` (32/0) | comp + 0.25 um | the n+ source/drain |
| contacts, `metal1` | a contact column on each strip, a contact row on one poly end | n+ and gate terminals |
| **no `nwell`** | | with an n-well the same shape is `cap_nmos_03v3_b` -- a different device |
| **no `dualgate`** | | would make it a 5/6 V class |

Terminals, from the deck (`moscap_extraction.lvs`): `tA => poly2_con`
(netlist terminal 1, the gate), `tB => nsd` (terminal 2, the n+ diffusion).
The schematic ties terminal 1 to `VDD_VCO` and terminal 2 to `GND_VCO`.

Arrangement (`block.decap_plan()`): a column to the right of the CLK column,
inside the `GND_VCO` ring, level with the `VDD_VCO` pin. The lower device's
gate row is centred on the pin's own y, so its Via1s land directly on the
Metal2 line that already ran from the supply trunk to the n-well tap ring; the
upper device is fed from that line by a short Metal2 spine. All four n+
columns are joined by one Metal1 bar between the devices, which runs on to the
block's `GND_VCO` ring band.

**Why the block grew.** The old markers sat at (31.06, -3.0)-(133.06, 47.0) um,
on top of the V-to-I core and the resistor block; they were never in free
space. There is no free 50 x 50 um area anywhere inside the folded block
(`PROOF-fold.md`), so the pair is a new column: the block's content width
grows by 54.17 um (decap pitch 51.2 um + spine and clearances).

Both polarity and count are visible in the extracted netlist, not only in a

## The device class, proved on a minimal cell first

`python3 -m harness.decap_proof --outdir <dir>` (from `layout/`) draws one 50 x
50 um device and four variants; each was run through the foundry LVS deck
against a one-card reference of class `cap_nmos_03v3`
(`minimal-device/summary.txt`, per-variant `lvs-*/`):

| Variant | LVS | Extracted capacitor(s) |
|---|---|---|
| `good` | match | `C$1 VDD_VCO GND_VCO ... cap_nmos_03v3 A=2500P P=200U` |
| `swapped` (the two net labels exchanged) | match | `C$1 GND_VCO VDD_VCO ...` -- terminal 1 is the poly gate, so the order is the polarity |
| `no_device` (no `mos_cap_mk`) | **mismatch** | none: the gate region is an ordinary NMOS |
| `class_b` (an n-well added) | **mismatch** | `cap_nmos_03v3_b` (plus a stray `cap_nmos_03v3`): the `_b` class is not the schematic's |
| `shorted` (gate row joined to the n+ bar) | **mismatch** | one-net capacitor |

An isolated capacitor is topologically "two nets and a cap", so the minimal
cell cannot show an *open* terminal; that needs the block.

## Limitations (stated, not papered over)

1. **Electrical behaviour is not simulated.** The drawn devices are checked
   for class, size, count and connectivity; ESR through a 50 um poly bar fed
   from one end, or the substrate resistance under a 51 um device whose
   nearest tap is the ring on the right, is not extracted or simulated here
   (#18). The gate bar is contacted along one end only, by design.
2. **No top-level LVS** (#149); the assembled `GND_VCO`/`VSS` substrate
   question there is unchanged.
3. **No density or antenna DRC** (deck defaults off); the new 2,500 um^2 gate
   on `VDD_VCO` has an `unchecked` antenna verdict like every other gate in the
   ERC report.
4. **The decap column adds 54.17 um to the block's width**; compaction (for
   example folding the pair into free area after a re-fold) is not attempted
   here.
5. `klayout-tools`: nothing awkward enough to file. `klt erc` ran as before.
