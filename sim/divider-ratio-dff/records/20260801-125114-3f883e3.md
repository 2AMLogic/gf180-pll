- **Methodology / criteria / limitations**:
  - Setup: 10 copies per bank share one clock; copy i sees its data 50% crossing ti before the clock's 50% crossing, ti = 1.00, 0.20, 0.10, 0.05, 0.02, 0.00, -0.02, -0.05, -0.10, -0.15 ns. Bank A captures 0->1, bank B captures 1->0. Setup time is the smallest ti whose clk->Q has not degraded by more than 10% against the same bank's ti = 1.00 ns reference -- the standard degradation criterion. Each ladder step's clk->Q is a raw_measures trig/targ .measure marked 'optional': a step past the flop's true setup time fails to capture within the td=20ns window, which ngspice reports as a failed .measure -- the harness records that as not-measured data (sim/harness README 'Expected .measure failures') rather than discarding the point, which is exactly what makes the ladder scan (testbench/derive.py, a sim/harness 'derived' measure) able to tell 'violated' from 'not simulated'.
  - Hold: 10 further copies (bank C) hold data low through the measured edge and transition 0->1 only th afterwards, th = 0.50 ... -0.70 ns. Hold is met at a step if Q stays below 10% of the rail until the next clock edge -- an avg measurement, which cannot fail, so bank C's raw_measures are required rather than optional.
  - The first clock edge preconditions every flop and the second (25.05 ns) is the one measured, so no result depends on the DC operating point of a bistable latch; every output measurement carries td=20ns for the same reason (see testbench/tb_dff_setup.sp header for the ff/125C failure mode this guards against).

Where the reported setup equals the last ladder step (-0.15 ns) the criterion was never tripped, so the true setup time is at or below that value and the number is a bound, not a measurement. That is the safe direction for the retiming margin computed downstream only because the bound is pessimistic: a smaller true setup can only increase the margin.
