- **Claim**: #527 -> spec/pll.md#lock-detector-window-trim-code-rule, via DR-022 Decision 5 route 1. The trim rule is normative and its measurand is internal: t_win is the ERR -> ERRD delay of delaywin_3v3 and neither node is a port of pll_top. DR-022 measured every quantity pll_top's pads DO expose against it and found none that selects the code to the accuracy spec/pll.md's Lock detector row assumes, leaving the rule executable only in simulation. Its Decision 5 names two candidate routes and authorizes neither; this record characterizes the first, the one that needs no design change and no new pad. With the loop locked, step REF's phase by a known signed Delta -- once, instantaneously -- and watch the design's own LOCK output. The detector sees phi_ss +/- Delta immediately while the loop's <= 430 kHz bandwidth takes microseconds to absorb the step, so the two step directions give Delta+ = t_flag - phi_ss and Delta- = t_flag + phi_ss, whose mean is t_flag with the static offset CANCELLED and whose half-difference is phi_ss. The question is not whether that algebra is right but whether the thresholds a tester would actually measure obey it: does the deassert happen and is it observable at the pad; does the threshold in Delta reproduce t_flag or a larger, integrator-limited quantity; does the +/- cancellation survive the loop's own asymmetric correction; and what Delta resolution does one trim step demand of the instrument.

- **Methodology / criteria / limitations**:
  - ONE deck, one ladder, one reduction. Each point is a closed-loop pll_top transient that warm-starts at this corner's own predicted lock control voltage, runs nstep reference cycles, steps REF's phase by this point's signed Delta at a single instant, and runs 20 more reference cycles. The threshold Delta+/Delta- is a reduction over the Delta axis at one (bundle, code) cell -- testbench/derive.py -- not a per-point number.
  - The phase step is exact by construction, not generated. Two identical periodic sources whose start times differ by exactly `delta` are selected between at an instant when both are at 0 V (0.2 reference periods before the nominal step boundary, 0.3 periods after both high plateaus ended), so the step introduces no stimulus glitch and no edge-placement rounding. Every point measures the achieved step (`delta_meas`, the REF period straddling the boundary minus the nominal period) and the record checks it against the requested one, so a stimulus that did not do what the manifest asked is a failed point rather than a silently wrong threshold.
  - Operating point: f_out = 100 MHz, f_ref = 12.5 MHz, N = 8, Icp trim code 2, VCO band 5, warm-started from the per-(bundle, temperature, supply) control voltage sim/supply-sensitivity derives from #8's committed f(Vctrl) record (sim/vco-tuning-range/corners/20260731-175947-0a12e6c/vco_tuning.csv) and the ratified band-selection rule. That campaign is the reason this operating point and not another: it is the only committed closed-loop cell in this tree where the flag is known to ASSERT in steady state at the rule's own trim code, and its 45-point steady-state grid reports LOCK at the rail and a settled static offset of -0.018 .. 1.052 ns at every MOS bundle at 27 C / 3.30 V (record 20260901-155456-46b92f8, supply_steady.csv). A procedure that reads a deassert threshold needs a part whose flag was asserted to begin with; at f_ref = 25 MHz / N = 6 / 150 MHz (sim/period-jitter's cell) the settled offset is 2-4 ns at most points and LOCK is legitimately low, so no threshold exists to measure there. The band code is the one the normative band-selection rule picks at 27 C for all five MOS bundles (band 5), so this is not a conveniently-chosen configuration: DR-025 is explicit that a run at a band the rule does not select is not evidence about a rule-compliant part.
  - Each bundle runs at the code the trim rule itself selects for it at the reference condition -- typical 7, ff 11, ss 3 -- transcribed from sim/lock-window-trim's committed code table and independently re-derivable from sim/lock-window-proxy's committed 16-code window map (record 20260925-050022-6d57802, raw_measures.csv, 27 C / 3.30 V rows). Three bundles rather than one because those are the three DISTINCT codes the rule selects across the five MOS bundles, and because ff's code 11 sets the trim MSB: it exercises LDT3 through the assembled part's own wiring of it, which only became possible with DR-026 (#515).
  - The reference t_flag each threshold is graded against is NOT measured by this deck. It is 1.037 x t_win at that (bundle, code, 27 C, 3.30 V) point, with t_win from the committed 16-code map above and 1.037 the flag-to-chain ratio spec/pll.md records from sim/lock-detector's own 205-point in-situ characterization. Measuring it here would mean probing the internal node whose inaccessibility is the entire problem, so the grading is against committed evidence instead -- and the 1.037 ratio is itself an f_ref = 25 MHz number applied at f_ref = 12.5 MHz, which the record states as a limitation rather than hides.
  - The verdict is taken from LOCK, the pad. v(xdut.vwin) -- the detector's integrator node, of which LOCK is a Schmitt trigger -- is measured alongside as a continuous stand-in for the same threshold crossing, because a binary search needs of order nine transients per threshold and a graded observable brackets the same crossing from a ladder. Where the two disagree, LOCK is the answer and vwin is the explanation.
  - The loop's own settled static offset is measured directly, two independent ways, over the last two pre-step reference cycles: the REF -> FB skew, and the PFD's UP/DN pulse-width difference (w_up - w_dn, which equals the skew for a reset-type PFD). That is the same cross-check sim/supply-sensitivity's tb_supply_lock.sp applies. It is the ground truth the bisection's OWN derived phi_ss = (Delta- - Delta+)/2 is compared against, which is how the +/- cancellation is tested rather than assumed.

The pre-step transient is identical for every Delta by construction (the two sources are selected between after it), so a drift biases all of a bundle's thresholds together rather than differently -- but the record reports the number instead of relying on that argument.

  **bisection_thresholds** (derived) — the procedure executed, per bundle: the bracketed phase-step threshold in each direction, and the two quantities the symmetric pair is supposed to yield -- t_flag with the static offset cancelled, and the static offset itself -- each against its own committed reference

  held_ps / dropped_ps are the largest |step| that left LOCK asserted and the smallest that dropped it. resolution says which of three things the ladder actually resolved, and the three are not interchangeable: `bracketed` (a rung held and a larger one dropped -- theta_ps is the midpoint and hw_ps its half-width), `lower_bound` (every rung held -- theta_ps is the largest of them and the true threshold is ABOVE it, so every derived number is the least unfavourable value consistent with the data), or `upper_bound` (the smallest rung already dropped). hw_ps is blank for a bound, because a bound has no half-width. A fourth value, `no_baseline_assert`, means the flag was NOT asserted before the step at this bundle -- its loop settled at a static offset wider than its own window -- so there is no threshold to bracket and every derived cell is left empty rather than filled from rungs that only re-observe an already-low flag.

  **tier_verdict** (derived) — the grading, in trim codes: the procedure's measurement error converted through the measured per-code step of that bundle's own window ladder, against DR-022 Decision 2's two accuracy tiers

  step_pct is the geometric mean of t_win(c+1)/t_win(c) over the fifteen adjacent pairs of the committed 16-code map at this bundle's own point -- the real step, not a nominal 4.7 %. one_step_ps is that fraction of the reference interval's midpoint: the picoseconds one trim code is worth here, and therefore what the instrument has to resolve. half_step_ps is the rounding budget the rule itself already spends.

  Tier A (DR-022 Decision 2) preserves the ratified [1, 2] ns band if the code error is never more than 2 low or 3 high.
