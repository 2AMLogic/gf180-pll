- **Methodology / criteria / limitations**:
  - Programming: N = 2^k + sum(p_i . 2^i) for i < k, with the one-hot chain-length code SEL_(k-1) = 1 terminating the modulus chain at the last active cell and selecting its output through the one-hot output mux. N is a static configuration (DR-001: glitch-free on-the-fly modulus switching is out of v1 scope), so each N is a separate point on this manifest's 'point' sweep axis (one id per (input rate, N) combination actually run, e.g. f200n64, f010n04), with ksel0..5/kp0..5 precomputed per the N->code formula above.
  - Start-up skip: every edge search begins one full output period (N VCO periods) after the clock starts. The thirteen flops leave the DC operating point in an arbitrary state and the modulus chain needs one full pass before its ripple-back signals are correct; measured without the skip the FIRST output period reads N-1 at some N and corners (seen at ff/-40 C/3.63 V for N = 12, 13, 16, 17) while every period after it is exact. Excluding a start-up transient by skipping it is honest; widening the tolerance until it disappears would not be.
  - Ratio criterion (testbench/derive.py 'ratio_pass'): the first settled retimed-FB period AND the un-retimed DIVOUT period over that same interval must both equal the point's programmed N to within 0.05 -- two nodes rather than one period twice, so a mis-read on either shows up as a disagreement between them. The tolerance sits an order of magnitude inside the 0.5 that would confuse N with N+-1 and an order of magnitude outside the .measure interpolation resolution (which scales with the max timestep, not with N). A checks entry ({'min': 1} on ratio_pass) turns any violation into a named check failure rather than a silent CSV column.
  - Retiming budget (testbench/derive.py 'derive_tables', table 'retiming_margin'): t_arr is DIVOUT's arrival referred to the VCO rising edge that caused it, taken modulo one VCO period -- that modulo is the point, because what threatens the flop is the arrival phase inside a VCO period, not how many whole periods the chain took. setup_margin = T_vco - t_arr - t_setup and hold_margin = t_arr - t_hold, with t_setup / t_hold joined per PVT point from sim/divider-ratio-dff's derived table (only at the N=64/200 MHz points, DR-001's own worst-case selection).
  - fbpw_s (testbench/derive.py) is FB high time, sign-corrected by adding N output periods when the DC operating point happens to start the chain in the state that makes the raw fall-minus-rise measurement come out negative -- the same correction tb_div23_cell.sp's runner applies for its own pulse widths.
  - N=64 (k=6, the longest chain and therefore the retiming-budget worst case) is the most expensive point in the campaign, so its grid is deliberately thinned to the low (2.97 V) supply, plus the nominal and fast-corner points, in the manifest's 'grid' blocks -- each carrying its own justification, rendered into this record's Corner matrix run field per sim/harness/README.md 'Sweeping beyond the PVT grid'.
  - Simulator settings: reltol 1e-3, abstol 1e-10, vntol 1e-5, chgtol 1e-13. Stop time is (3N + 20) VCO periods: the one-output-period start-up skip, then up to two more output periods to catch two FB rising edges after it, plus the retiming flop's own latency. Max step is VCO period / 100 for the N=64 point (both input rates, tied to the 200 MHz value in absolute seconds -- see the note below) and VCO period / 50 for the rest.
  - Note -- N=64's timestep override is a fixed absolute number (5e-11 s = 1/(100 x 200 MHz)), not a function of the run's own kf, because this manifest's sweep-axis parameters are static per point and cannot depend on a second axis. At the 10 MHz bottom-of-band check this is finer than the pre-harness runner used there (which scaled the override by kf), which only improves resolution and is deliberately kept simple since that check is ratio-only, not the retiming-margin claim (which is only ever evaluated at 200 MHz).
  - Limitation -- schematic-level, and it bites hardest here. There are no extracted parasitics and no routing load between cells, and the retiming margin is a difference of two numbers that both grow with parasitic load. A margin quoted here is an upper bound on the post-layout margin, not an estimate of it. This is the single most important number for #18 to re-take.
