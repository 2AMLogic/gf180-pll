# klt sim RECORD — divider-ratio-chain, remaining slices (#1090)

The #1083 pilot migrated the `f200n33` slice of `divider-ratio-chain` to a
`klt sim` request. This record extends the same pattern to the remaining
190 points of the committed f6eeac7 chain record
[`20261114-093804-ad9eef8`](../../records/20261114-093804-ad9eef8.md): the
full 45-point PVT grid at N = 4, the divisor sweep N = 5–32/34–63 at its two
stress corners, the 17 N = 64 retiming-margin points, and the 10 MHz
bottom-of-band checks — every (rate, divisor, process, temperature, supply)
key the record carries except the pilot's 45.

## What ran

- **Requests**: 63 circuit bodies + request JSONs under `netlists/` and
  `requests/`, generated by `generate.py` from the campaign's own committed
  inputs (`../../testbench/tb.json` point definitions; the
  `sim/divider-ratio-dff` join table for the pinned `tsetup_s`/`thold_s`).
  Each body is the pilot's `netlist-f200n33.sp` composition — point params
  and the four solver options pinned, `.include` of the committed DUT and
  stimulus — and each request sweeps supply as `corners.params` on
  `vdd_val`, carving the record's non-rectangular selections with
  top-level `exclude` rules:
  - `f200n04` — the full 5 × 3 × 3 grid (45 corners);
  - `f200n05`…`f200n32`, `f200n34`…`f200n63` — one request per divisor at
    SS/125 °C/2.97 V and FF/−40 °C/3.63 V (116 corners);
  - `f200n64a`/`f200n64b` — the 17 retiming points, split by the two
    distinct joined `tsetup_s` values (2e-11 s: 4 corners; 5e-11 s: 13
    corners) so the per-PVT join is pinned in each body and
    `setup_margin`/`hold_margin` are request measurements with
    `limits {min: 0}` tagged `spec_row: retiming-margin`;
  - `f010n04`/`f010n64` — five processes at 125 °C/2.97 V plus
    typical/27 °C/3.30 V per divisor (12 corners).
  Ratio limits ([N − 0.05, N + 0.05], `derive.py`'s tolerance) ride on
  `n_fb`/`ndo` in every request, tagged `spec_row: multiplication-ratio`.
- **Key-set check**: `plan_check.py` dry-ran all 63 requests and verified
  the expanded 190-corner (rate, divisor, process, temperature, supply) key
  set equals the committed record's minus the pilot — no duplicates, none
  missing, none extra (run before submission; output on #1090).
- **Execution**: one `klt sim --batch-set <63 requests> -o runs
  --wait-for-capacity 600 --max-in-flight 8`. The submitting client was
  killed mid-wait by a session tool timeout with 50 members collected; the
  set was finished with the same command plus `--resume`, which re-derived
  the outstanding members from their shard maps and collected their
  already-running fleet jobs. Aggregate envelope: `status: pass`,
  63/63 members pass, 0 refused.
- **Envelopes**: `runs/<stem>/report.json` per member (the paths of record
  are the aggregate's `requests[].report`); `runs/set-manifest.json` maps
  every request to its fleet job ids. 190/190 corners PASS, 0 failed,
  0 errored, 0 inconclusive across the set.

pilot's 21 s/µs ⇒ roughly 85 single-threaded minutes. Actual: 77 spot jobs
