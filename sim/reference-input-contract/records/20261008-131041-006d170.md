- **Methodology / criteria / limitations**:
  - **What is swept is the STIMULUS, not the DUT.** `spec/pll.md`'s Reference input row states three electrical limits on the driving system -- levels (V_IL <= 0.2*VDD, V_IH >= 0.8*VDD), edge rate (<= 5 ns, 10-90 %) and duty cycle (30-70 %) -- and every one of them was **budget**: each of the testbenches in this repository that drives REF drives it identically, as an ideal full-rail pulse with 200 ps edges and exactly 50 % duty, so the three limits were conditions no simulation had ever varied. This campaign holds the DUT at exactly the operating point `sim/pfd-deadzone` characterizes (`pfd_cp`, 25 MHz reference, Vctrl = 1.65 V, Icp trim code b1 b0 = 10) and sweeps the REF **waveform** to each stated boundary instead.
  - **Criterion: the reference-path set delay `d_ref`.** `d_ref = t(UP crosses VDD/2, rising) - t(REF crosses VDD/2, rising)` is the interval between the reference edge as a driving system would time it and the instant the phase detector acts on it -- i.e. it *is* "the phase the PFD sampled". At lock the loop drives `(t_ref + d_ref) = (t_fb + d_fb)`, so a reference waveform that shifts `d_ref` shifts the locked loop's whole reference-to-output phase relationship by the same amount. The verdict quantity is therefore the **shift**, `dphi_shift = d_ref(variant) - d_ref(ideal)`, evaluated per PVT corner against the ideal pulse every prior record used.
  - **The mid-rail crossing is the timing reference, and it is the only one that works.** All six waveform variants swing symmetrically about VDD/2 (a 0.2*VDD - 0.8*VDD swing is centred on 0.5*VDD exactly), so the rising 50 %-of-VDD crossing is well defined for every one of them and is the ordinary convention for timing a CMOS clock. The deck places each pulse by that crossing (`pulse` delay = `tmid - 0.5*trf`) rather than by its `pulse()` delay argument, so the applied phase error is the `p` axis and nothing else; aligning on the pulse delay would have folded half of a 6.25 ns edge into the phase error and read the slow-edge variants as a 3 ns phase step.
  - **Two acceptance bounds, each taken from the ratified spec rather than from the data.** (a) **Duty**: `spec/pll.md`'s duty row argues from `design/pfd.sch` that the edge detectors fire on the **rising** edge only, so duty "affects only pulse-width margin, not the sampled phase". Its falsifiable form is `|dphi_shift|` at 30 % and at 70 % duty <= **1 % of `d_ref`** at that corner -- a scale-free bound of order 10 ps here, so the claim is tested rather than restated. (b) **Levels and edge rate**: a reference-induced shift of the sampling instant is indistinguishable, at the detector's input, from static phase error, so it is graded against the **1 ns static-phase bound** of the [Lock criterion](../../spec/pll.md#lock-time) -- `|dphi_shift| <= 1 ns` at every corner for every in-contract waveform. Neither bound was chosen after seeing a number.
  - **The record proves its own stimulus was inside the contract.** `slew_ref` measures the 10-90 % edge time and `thigh_ref` the mid-rail high span **of the applied waveform** at every point, and both are gated (`slew_ref <= 5 ns`; `duty_ref_pct` inside 30-70 %). So the contract limits are measured conditions of the record, not assertions read off the `pulse()` arguments -- which is the failure mode that left this row as budget in the first place.
  - **`d_fb` is the experiment's own control.** FB is driven by a byte-for-byte identical ideal pulse at every point of the sweep, and `d_fb` is the same set delay measured down that path. Any movement of `d_fb` across the waveform axis would be a defect in this deck rather than a property of the reference contract, so the per-corner verdict table carries `dfb_dev_max` -- the largest deviation of `d_fb` from its ideal-waveform value at that corner -- and the verdict fails if it exceeds the same 1 %-of-`d_ref` bound the duty claim is held to.
  - **Source quality: an input-side transfer measurement, not a closed-loop jitter number.** `spec/pll.md` excludes reference-source quality from the jitter and spur budgets and states the 20*log10(N) transfer (12 dB at N = 4 to 36 dB at N = 64) an integrating system must budget against. This campaign does **not** convert that into an output-referred jitter limit -- that needs a closed-loop reference-perturbation bench which does not exist here. What it does supply is the **input side** of it, which no record carried before: (i) `kd`, the detector gain measured from the near pair at +/-200 ps, taken at the ideal reference **and** at both slow-edge variants at three binding corners, so the record can say whether a legal reference degrades the gain the loop's bandwidth depends on; and (ii) `dtdv_worst`, the AM-to-PM coefficient at the worst legal reference slope, derived per corner from the measured edges -- the seconds of sampling-instant displacement per volt of reference amplitude noise, which is the coefficient an integrator needs to turn its own reference's amplitude noise into a phase contribution. The exclusion itself is restated, with an owner, in the decision record this campaign is cited by.
  - **Effective input trip point, extracted rather than assumed.** For a linear input ramp the set delay is `d_ref = d0 + (Vth_eff - VDD/2) / s`, where `s` is the mid-rail slope and `Vth_eff` the effective switching threshold of the REF input path. The ideal (200 ps) and 5 ns-edge points at the same corner are two slopes at one corner, so the pair solves for both unknowns: `vth_off = Vth_eff - VDD/2` is reported per corner in volts, and the model is then **checked** against the `wworst` point (a third, independent slope at reduced levels) -- the verdict table's `vth_model_resid` column is that prediction's residual, not a fit quality.
  - **One ngspice invocation per (PVT corner, waveform, phase-offset) point**, as in `sim/pfd-deadzone` and for the same reason: several copies of this DUT in one deck, each with its own ideal control-node source carrying the DR-005 dump-node buffer's displacement current, do not co-converge.
  - Reference 25 MHz (40 ns period) -- the TOP of DR-002 Decision 1's ratified 1-25 MHz v1 range, deliberately the demanding end for this claim: a 5 ns 10-90 % edge is 15.6 % of a 25 MHz period and 0.6 % of a 1 MHz one, so a result that holds here holds for every slower reference in the range. Transient: 3 reference cycles at a 20 ps maximum timestep, `reltol` 1e-4 / `abstol` 1e-14, charge integrated over the last two cycles and halved, the first cycle discarded as startup -- identical to `sim/pfd-deadzone`, so the charge numbers of the two campaigns are directly comparable.
  - **Limitation (open loop).** The control node is held at 1.65 V by an ideal source and FB is an idealized buffered edge, exactly as in `sim/pfd-deadzone`. This measures what the reference contract does **to the phase detector**; it does not run a closed loop, so it reports a *shift of the sampling instant* and not a settled loop error. That distinction matters for reading the result: a constant `dphi_shift` moves the locked reference-to-output phase and is not itself a loop error, while a `dphi_shift` that varies across the PVT grid is wander the loop must track -- both are reported.
  - **Limitation (nominal skew only).** `sw_stat_global = sw_stat_mismatch = 0`; random device mismatch is `sim/mc-cp-mismatch`'s campaign (#15). The detector-gain sub-grid is a declared 3-corner slice, not the full 45 -- see the Corner matrix run field for its justification.
  - **Axes not swept**: passive corner sections (`res_*`, `mimcap_*`, `moscap_*`) N/A -- the DUT contains no resistors or capacitors, only `nfet_03v3`/`pfet_03v3` (DR-002 Decision 3). The 2-bit Icp trim is held at b1 b0 = 10, as in `sim/pfd-deadzone`: the unit-element construction runs the same per-leg current at every code, and the reference-path set delay this campaign measures is upstream of the pump entirely.
  - **Also not swept: reference frequency.** The whole campaign runs at 25 MHz. The contract's three limits are all *shape* limits, and 25 MHz is where each of them consumes the largest fraction of a reference period, so it is the binding end of the ratified 1-25 MHz range for all three. A reference-frequency axis would re-measure `sim/loop-dynamics`' and `sim/lock-time`' coverage of that axis, which is already recorded.
