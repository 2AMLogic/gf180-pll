## What this circuit does

Four cooperating pieces, all summed into one output node `VBP0` — see
`vtoi_core.py`'s own module docstring for the full read (device-by-device,
citing `design/vco_bias.sch`):

1. **Constant-gm (beta-multiplier) reference** — `MP1`/`MN1` (diode branch,
   node `NA`) sets `MN2`'s gate; `MN2` is source-degenerated through `RCG`
   (node `NC`) against `MP2`'s own diode-connected drain (`VBPC`).
2. **Startup** — `MSU1` (gate tied permanently to `GND_VCO`, an always-on
   weak pull-up) and `MSU2` (gated by `NA`) drive node `NSU`; `MSU3` uses
   `NSU` to kick `VBPC` low at power-up.
3. **2×Vgs stacked reference** — `MPR` (gate `VBPC`) stacks over
   diode-connected `MD1`/`MD2` (node `NMD` between them) to produce `VFIX`.
4. **Offset + source-degenerated V-to-I + summing** — `MOFF` (gate `VFIX`,
   degenerated by `ROFF` via `NOFF`) and `MVI` (gate `VCTRL`, the block's
   external control-voltage input, degenerated by `RDEG` via `NVI`) both
   land on `VBP0`, diode-mirrored by `MSUM` (`nf=4`) — `VBP0` is exactly the
   net `mirror.py`'s cascade A already consumes
   (`devices.CASCADE_A.always_on.gate_net == "VBP0"`).

## Why this is its own block, not merged with `bias_resistors.py`

`RCG`/`ROFF`/`RDEG` are already drawn, DRC-clean and standalone by
`bias_resistors.py` (PR #314). This increment draws every V-to-I core
*transistor* as its own standalone block and exposes `NC`/`NOFF`/`NVI` as
Metal2 boundary pins using **the exact same net names**
`bias_resistors.py` already uses for its own `top_net` pins — verified by
`test_resistor_nets_match_bias_resistors_top_nets` — so wiring the two
blocks together under one shared guard ring is a well-defined mechanical
follow-up, not a re-derivation.

## Routing: reusing `mirror.py`'s Metal2 mesh, not re-deriving it

Several internal nodes (`VBPC`, `NSU`, `VFIX`, `VBP0`) are needed from
**both** the NMOS and PMOS rows — the same "mesh, not a chain" topology
`mirror.py`'s own module docstring names as the reason for Metal2 tracks.
`vtoi_core.py` reuses that exact construction (per-terminal Metal1 escape
up/down to a Metal2 track; two-track-group split for two-row nets, tied by
one Metal1 link column) rather than inventing a second routing scheme.
Every device here is an ordinary single- or multi-finger MOSFET (no
common-centroid array), so `mirror.py`'s cascade-specific code has no
counterpart here. `MSUM` (`nf=4`) is the one multi-finger device; its four
fingers are drawn side by side and bused on all three terminals.

## The one device NOT mesh-routed: `MSU1`'s gate

`MSU1`'s gate ties permanently to `GND_VCO` (an always-on weak pull-up),
not a mesh net. Routing it through the general escape/track mechanism would
need a dedicated `GND_VCO` track plus an anchor wire crossing the entire
NMOS row's height. Instead `MSU1` is placed **last** (rightmost) in the
PMOS row (`devices.VTOI_PMOS_ROW`'s own ordering), and its gate pad is tied
with a single horizontal Metal1 run — at the gate's own height, entirely
within the PMOS row's own vertical span — straight into the guard ring's
right-hand band (already `GND_VCO`-tied via `primitives.guard_ring()`).

## A real DRC violation this generator hit, and the fix

`MSU1`'s schematic `W=0.22 µm` is narrower than
`primitives.MIN_SD_CONTACT_WIDTH_UM` (0.42 µm — `CONTACT_SIZE_UM` +
`2*CONTACT_ROW_MARGIN_UM`). Drawing it with the existing single-width
`mosfet()` generator produced a real `CO.4` (comp overlap of contact,
0.07 µm min) violation: `_contact_positions()`'s own "span narrower than
one contact" fallback centered a full-size contact in a comp island too
narrow to enclose it.

**Fix**: `primitives.mosfet()` gained a `min_sd_width_um` parameter that
draws a **dog-bone** — the channel (gate) region stays exactly `w` wide (W
is unchanged), but the two S/D comp islands widen, symmetrically about the
same centerline, to `max(w, min_sd_width_um)`. The first version of this
fix put the wide-to-narrow step exactly at the gate's own `y1`/`y2`
boundary, which produced four new `PL.4_LV`/`PL.5a_LV`/`PL.5b_LV`
violations: the gate bar's own endcap flanks (poly beyond the narrow
channel, legitimately "field poly" there) sat directly adjacent to the
*wide* S/D comp just below/above, a zero-clearance touch under
`PL.5a_LV`/`PL.5b_LV`'s 0.1 µm field-poly-to-comp minimum. The final fix
(`primitives.DOG_BONE_SETBACK_UM = 0.5`) keeps the step at least 0.5 µm
clear of the gate boundary on each side. Both violation classes are
documented in `primitives.py`'s own constant/function docstrings, not just
here — future dog-boned devices inherit the fix automatically.

When `min_sd_width_um` is `None` or `<= w` (every existing caller),
`mosfet()` draws exactly the same single-rectangle comp as before —
verified by the regression check below (bit-identical GDS on every layer
for `ring.py`/`mirror.py`/`buffer.py`/`bias_resistors.py`) and by
`DogBoneMosfetTests.test_no_widening_when_min_sd_width_is_none_or_below_w`.

## Tap pitch (test plan edge case)

Checked independently in pure Python
(`vtoi_core.max_pmos_tap_distance_um()`/`max_nmos_tap_distance_um()`,
`layout/tests/test_vco_layout.py`'s `VtoiCoreTapPitchTests`), not inferred
from "the DRC run passed":

| Row | Worst-case in-plane distance to nearest tap | Bound (PLL-FLOORPLAN.md §1) |
|---|---|---|
| PMOS (n-well tap bands) | 12.10 µm | ≤ 15 µm |
| NMOS (outer p-ring) | 6.52 µm | ≤ 15 µm |

**Why this block needs a top *and* a bottom n-well tap band**, unlike
`ring.py`/`mirror.py`/`buffer.py`'s single top band: `MSU1`'s deliberately
long `L=20 µm` channel makes it, by construction, the tallest device in the
PMOS row — it spans the row's *entire* height. A single top-only band would
leave its own lower half more than 15 µm from any tap. Two bands (top and
bottom, both making ohmic contact to the same continuous n-well body, so no
extra Metal1 jumper is needed between them) bound the worst case at half of
the tallest device's own height plus one gap (12.10 µm) instead of the full
height (23 µm) — comfortably DRC-clean, though with less margin than the
other VCO sub-blocks' own `< 7.5 µm` (half the bound) convention, since
`MSU1`'s own channel length is the dominating constraint. This is disclosed
explicitly rather than tightened artificially:
`test_pmos_tap_pitch_has_real_margin_not_just_barely_under` asserts
`< 13.0 µm`, not `< 7.5 µm`.

## Footprint vs. `skeleton.py`

| Block | Real footprint | Area |
|---|---|---|
| `vco_vtoi_core` | 121.18 × 50.72 µm | 6,146 µm² |

`layout/floorplan/skeleton.py`'s `VCO_VTOI_CORE` now carries this real
footprint, stacked alongside `VCO_MIRROR`/`VCO_RING`/`VCO_BUFFER` inside
`VCO_CORE`. **`VCO_CORE.h` grows past the 100 µm ROM value for the first
time** (100 → 144.78 µm) — four real sub-blocks stacked with margin no
longer fit it, and `VCO_VTOI_CORE`'s own 50.72 µm height (driven almost
entirely by `MSU1`'s L=20 µm channel) is the largest single addition.
`VCO_CORE.w` is unchanged (`VCO_VTOI_CORE_W`=121.18 µm is narrower than the
mirror's own 269.86 µm, which still sets the block's width).

**Whole-skeleton area budget is unaffected by this**, disclosed rather than
silently glossed over: `skeleton.total_extent_um2()` is
**145,247.7 µm² both before and after this increment** — the whole-skeleton
bounding box is dominated by `LOOP_FILTER`'s own 195 µm height, not
`VCO_CORE`'s, so `VCO_CORE.h` growing from 100 to 144.78 µm has not (yet)
crossed the skeleton-level PLL-FLOORPLAN.md §5 0.15 mm² draft target. It is
real headroom being consumed at the *block* level, though — `VCO_CORE`'s
own rectangle grows from 27,986 µm² to 40,514 µm² (~45%), and its height
now has room only up to `LOOP_FILTER.h` (195 µm) before it — rather than
`LOOP_FILTER` — becomes the skeleton's own height driver.
