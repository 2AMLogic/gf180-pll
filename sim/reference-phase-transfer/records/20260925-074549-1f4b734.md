- **Methodology / criteria / limitations**:
  - MEASUREMENT, NOT DERIVATION. spec/pll.md's Reference input row excludes reference-source quality from this block's own jitter/spur numbers and states a 20*log10(N) in-band transfer from theory alone -- no testbench in sim/ had ever perturbed REF in time and read the consequence at the output; every closed-loop record before this campaign drives REF from a perfectly periodic pulse source. This is that measurement: a KNOWN, single reference-phase STEP is applied at `tphase` and the loop's own re-tracking is read out via its REF-vs-FB static phase error, which is exact (not statistical) because the divider is a digital ratio.
  - DIFFERENTIAL AGAINST A PAIRED CONTROL RUN -- the correction this record makes to 20260925-073001-ed38ff1. That record differenced phi AFTER the step against phi BEFORE it inside ONE run, and the differencing was confounded: at this release point the loop's static phase error is still winding at ~1e-4 fractional frequency error 9.2 us in (0.12-0.19 ns/us, monotonic at every corner, consistent with the +72 ppm the same points measure on `ffb`), so the baseline moved 0.4-1.4 ns across the 6.4 us between readings, against a 1 ns step. Subtracting a drifting baseline from a step response measures their sum. So each PVT point now runs TWO decks (`phases`): `ctl` with the step selector `apply` = 0, and `stp` with `apply` = 1. They are bit-identical up to `tphase` -- same netlist, same PVT point, same `.ic` release, same blend gate -- so the winding baseline is common-mode BY CONSTRUCTION, and d(t) = unwrap(phi_stp(t) - phi_ctl(t)) is the step response with the drift removed rather than assumed small. `drift_ctl` reports the drift the control run alone saw, so the record states the size of what the pairing cancelled instead of hiding it.
  - THE PAIRING IS CHECKED, NOT ASSERTED. `pair_resid` = d(`ta`), read before the step at an instant where the two decks are still the same run, must be zero. It is checked at +/-1 ps -- a tighter band than anything else here, because it is not a physical quantity: a nonzero value means the two decks diverged before `tphase` and the whole differential is void. This is the check that makes the control run evidence rather than an assumption.
  - WHY A STEP, AND WHY NOT DIRECTLY ON THE OUTPUT. #509 accepts a deterministic single-step or single-tone bench as the cheap first increment -- no noise/spectral methodology needed. A phase step's residual, read many loop time constants later, IS the loop's deep-in-band (near-DC) transfer, which is exactly the regime spec/pll.md's 20*log10(N) line describes ('inside the loop bandwidth'). The output itself is not measured directly: for N at the top of the ratified 4-64 range the output period is short enough that N*dphi (the theoretically expected output-phase excursion) exceeds a whole output cycle long before dphi is large enough to resolve against 200 ps edge rates and solver noise -- the wraparound this note exists to flag. Reading the untouched REF-vs-FB static phase error instead sidesteps that: FB's own excursion is at most a few nanoseconds (dphi itself), always well inside one reference period, and the divider (CLK = N*FB, an exact digital ratio) carries that same fractional tracking onto the output without needing to resolve it directly.
  - FOUR INSTANTS, AND THE ROLL-OFF COMES FREE. d is read at four instants. `ta` (2.6 us, BEFORE the step) is the pairing check above. `tfast` (120 ns after the step, i.e. 0.3-1.2 of the 100-400 ns loop time constant sim/loop-dynamics measured at this operating point) is the transfer to a perturbation FASTER than the loop can follow: the loop has barely begun to re-track, d is near -dphi, and the transfer is near ZERO rather than N -- which is the roll-off ABOVE the loop bandwidth the same spec paragraph asserts, in the time domain and at no extra cost. `tc` (3 us after) and `tb` (6 us after) are the settled in-band readings, 15-60 time constants out and 3 us apart so `settle_resid` = d(tb) - d(tc) is the run's own proof it waited long enough rather than a claim that it did. The in-band number the record reports is read at `tb`.
  - HOW THE STEP IS APPLIED. Two ideal periodic pulse trains (`refa`, unperturbed; `refb`, identical but delayed by `dstep` = `dphi`*`apply`) are blended through a fast (200 ps) linear gate that switches from refa to refb at `tphase`, placed in the middle of a reference LOW gap common to both trains so the blend never sees the two disagree -- REF is refa exactly before tphase and refb exactly after, a genuinely glitch-free stitch. Verified in isolation (a standalone prototype .tran trace) before this deck was written: one clean 41 ns gap against a background of 40 ns gaps, nothing else moved. In the `ctl` deck `dstep` is 0, so refb IS refa and the same gate blends two identical signals -- the gate's own blend transient is therefore common-mode as well, and cancels with the drift.
  - OPERATING POINT, REUSED FROM sim/reference-spur ON PURPOSE. N = 6, VCO band code 6, Icp trim code 0 (one unit leg, the trim-code rule REQUIRES it there per spec/pll.md from DR-006 Decision 5), f_ref = 25 MHz, f_out = 150 MHz -- the identical operating point sim/reference-spur (#145) already measured at this exact PVT subset. This campaign's `vstart` release table is that record's own vco-tuning-range-derived values (record 20260804-162735-72883fb, band 6), reused verbatim rather than re-derived, because it is the same (N, band, f_out) triple -- see sim/reference-spur/testbench/vstart_from_vco_record.py for the derivation this campaign cites rather than duplicates. N = 6 is inside the ratified 4-64 range; this record measures at that one value. The mechanism the record measures -- a type-II loop's DC phase tracking, and an exact digital divide ratio -- is structural rather than N-specific, but this record itself is evidence at N = 6 only; a second N would need its own vco-tuning-range-derived vstart table at a different (N, f_ref) operating point and is not run here (see Limitations).
  - dphi = 1 ns: about 2.5% of the 40 ns reference period (~9 degrees), comfortably larger than the 200 ps edge rate and solver-noise floor so the step is resolvable, and comfortably smaller than the reference LOW gap (half a period) so the stitch stays glitch-free and comfortably inside the loop's small-signal-tracking regime (no PFD dead-zone or CP-compliance-limit interaction is expected at this size).
  - STANDING GUARDS. dn_lvl (mean PFD DN level over the post-step window, in the stepped deck) is the closed-loop internal-timestep-bound self-check sim/README.md requires: a value near zero is proof the loop's set-pulse edges are being missed, which would fabricate a false 'the loop tracks' or 'does not track' reading rather than a real one. nmeas (= fout/ffb, both measured over the post-step window by counting edges) and fout independently confirm the loop is running at N = 6 / 150 MHz throughout the measurement window, not merely that FB and REF happen to read close together once. NOTE what these guards do NOT claim: `lock` (the design's own detector flag) does not assert at four of the five corners on this grid, and the differential measurement does not need it to -- see Limitations (6).
  - SIMULATOR SETTINGS. .tran 2n 9.2u 0 100p -- the fourth argument is the 100 ps ceiling on the ngspice INTERNAL transient timestep every campaign whose DUT contains the PFD inherits (sim/README.md, 'Closed-loop internal-timestep bound'). .option rshunt=1e12 itl4=200 reltol=1e-3 abstol=1e-13 vntol=1e-6 -- identical to sim/reference-spur's and sim/pll-top-smoke's, so this deck's converged solution is comparable with the other closed-loop campaigns'. Both phases run the identical analysis line; that is why `analyses` is declared once, shared.
  - CORNER MATRIX -- the SAME five-point subset sim/reference-spur runs, for the same reason stated there: one point here is a closed-loop transient of the whole PLL at a 100 ps internal-timestep ceiling, tens of thousands of internal steps, and the full 45-point cross-product at this run length is not affordable on the wall-clock this campaign has. Two decks per point makes it ten invocations, not five. The union spans every mandated axis (all five MOS bundles, all three temperatures, all three supplies) without being the full cross-product; the full-grid re-run remains owed, same as sim/reference-spur's.
  - LIMITATIONS. (1) One (f_ref, N, band, trim) operating point: N = 6 only. The mechanism measured (type-II DC phase tracking, an exact digital divide ratio) does not structurally depend on N, but this record is evidence at N = 6, not a swept confirmation across the ratified 4-64 range -- broader N coverage is follow-up work, not delivered here. (2) MOS-only sweep: res_typical/moscap_typical/mimcap_typical are held at typical at every point (same caveat as sim/reference-spur, and less consequential here -- the loop-filter R/C values set the loop's TIME CONSTANT, not its DC gain, and DC gain is what a phase step's long-settled residual actually probes). (3) Schematic-level: no layout parasitics. (4) The reference's OWN edges are ideal apart from the single deliberate step -- no reference jitter, no duty-cycle error; this measures the loop's transfer FUNCTION, not a jitter budget (spec/pll.md's Reference input row's own distinction), and it does NOT convert the exclusion into a numeric reference-jitter limit, which needs the noise methodology owed at #505. (5) TWO frequency points, not a swept transfer function: the settled reading is the deep-in-band (near-DC) transfer and `tfast` is one point above the loop bandwidth. A continuous magnitude-vs-frequency curve, and therefore the loop bandwidth read off this measurement rather than cited from sim/loop-dynamics, is a further increment. (6) The design's own `lock` flag does not assert at four of the five corners at this release point, and this record does not claim it does. The differential does not depend on it: what it needs is that both decks are the same run up to `tphase` (checked at +/-1 ps by `pair_resid`) and that the loop is tracking at N = 6 through the measurement window (checked by `nmeas`/`fout`/`dn_lvl`). Whether the detector asserts is a lock-detector-window question this repository already owns elsewhere (spec/pll.md row 16, sim/lock-detector, #437), not a defect in this measurement -- but it does mean this record is NOT evidence about lock, and must not be cited for it.
