# PFD block layout — mirror-symmetric transistor-level layout DRC run (issue #300)

Part 2 of #294 (itself one of #292's five block sub-issues), built on Part
1's (#299, PR #312) `layout/pll_top/pfd_cp/devgen.py` methodology. This is a
real, DRC-clean transistor-level layout of `design/pfd.sch` (the tri-state
PFD): all 47 leaf-cell instances — 40 `pfdcp_inv_3v3` + 7 `pfdcp_nand2_3v3`,
108 transistors — generated by `layout/pll_top/pfd_cp/pfd.py` and checked
with

```
python3 layout/run_pv.py drc <gds> --top pfd --run-dir <dir>
```

against the gf180mcu PDK's own foundry DRC deck (not `klt drc`'s curated
subset — see `layout/README.md`'s "Why this isn't `klt drc`" section).

## What this is, and is not

Every leaf instance is transcribed directly from `design/pfd.sch` +
`design/edgedet.sch` + `design/srlatch.sch` (flattened; see
`layout/tests/test_pfd_layout.py`'s `flatten_pfd()`, which parses the
schematics themselves rather than trusting a hand count) and drawn with the
same full-custom device/interconnect layers `devgen.py` established in
Part 1 (`comp` 22/0, `poly2` 30/0, `contact` 33/0, `nplus` 32/0, `pplus`
31/0, `nwell` 21/0, `metal1` 34/0, `metal2` 35/0, `metal3` 36/0, plus the
34/10 Metal1 *pin* purpose the official LVS deck reads net names from). It
is a **DRC-clean geometry claim only** — LVS (netlist-match against
`design/pfd.sch`) is not run here and is not claimed, per this issue's own
Acceptance Criteria (DRC-clean is the named gate; LVS is not). The block-
level connectivity claim this issue's Acceptance Criteria *does* ask for —
no shorts, no opens, every net one connected island, matching the flattened
schematic's port-to-net wiring — is instead checked directly on the drawn
geometry by `layout/tests/test_pfd_layout.py` (`BuiltLayoutTests`,
`SchematicTranscriptionTests`), which is a stronger, PDK-independent
substitute for the connectivity half of what LVS would otherwise catch.

`devgen.py`'s own `build_stack_cell()` could not draw this block directly —
`pfdcp_nand2_3v3`'s output `Y` has three device terminals (two PMOS drains
+ one NMOS drain), and `devgen`'s vertical-current-flow convention puts a
device's two S/D terminals at the same x, which cannot support the
per-net distinct-x-lane routing a 47-instance interconnected block needs.
`layout/pll_top/pfd_cp/rowgen.py` + `pfd_cells.py` are the composition
layer this block needed on top of `devgen.py`, exactly as `devgen.py`'s own
module docstring anticipated ("a block that genuinely needs a 2-D placement
... is out of this module's scope"); `devgen.py` itself is unmodified.

## Mirror symmetry (this issue's central claim)

The two UP/DN chains — `xed_ref`/`xlat_ref`/`xinv_sr` vs.
`xed_fb`/`xlat_fb`/`xinv_sf` — are drawn from the *same* local coordinates
through `rowgen.py`'s `MirrorView`, then independently verified on the
**emitted geometry** (not the construction) by
`layout/tests/test_pfd_layout.py`'s `BranchMirrorSymmetryTests`: every shape
on every layer inside the UP branch's window is clipped and compared,
shape-for-shape, against the reflection of the DN branch's window, and
every one of the 11 UP/DN net pairs in `pfd.MIRROR_NET_PAIRS` (`REF`/`FB`,
`UP`/`DN`, `UPB`/`DNB`, `PR`/`PF`, `SBR`/`SBF`, and the five internal
`xed_*.D1`-`D5` + `NN` edge-detector nodes) has a bit-identical, same-length
mirrored counterpart. The shared reset NAND (`xnand_rst`) straddles the
axis symmetrically (`test_reset_nand_straddles_the_axis_symmetrically`),
and the shared reset/delay chain's `RB` output fans out to both latches
over equal-length arms from a single axis-centered Metal3 link
(`SharedResetFanoutTests`).

## Results

| Check | Cell | Expected | Got | Verdict |
|---|---|---|---|---|
| 1 | `pfd` (full block, standalone) | clean | `Klayout DRC run is clean. GDS has no DRC violations.` | **PASS** |

Only one macro is committed here — unlike `lock-detector-layout/`, the
leaf cells (`pfdcp_inv_3v3`/`pfdcp_nand2_3v3`) already have their own
standalone DRC/LVS proof in `layout/evidence/pfdcp-inv-proof/` (Part 1);
re-proving them individually here would be a duplicate claim, not new
evidence.

Standalone footprint (bounding box, as-drawn): 80.900 x 22.480 um
(~1,818.6 um^2) — well inside `PLL-FLOORPLAN.md` section 5's 10,000-20,000
um^2 budget for the combined PFD + charge pump + dump buffer, leaving
headroom for Parts 3/4 (#301/#302).

## Friction

No new `klayout-tools` capability gap was hit in this increment — the
device/interconnect drawing primitives and the DRC/LVS harness are entirely
reused from Part 1 (#299) and `lock_detector`'s (#296) prior full-custom
layout work; the only new code here is pure-Python placement/routing logic
(`rowgen.py`, `pfd_cells.py`, `pfd.py`) with no `klt` interaction of its
own.
